# 주간 경쟁사 동향 · 4단계 수동 AI 검토 보조

[사이트 열기](https://iesilder.github.io/kw-plan-weekly-trend/) · [수동 수집 워크플로](https://github.com/iesilder/kw-plan-weekly-trend/actions/workflows/pipeline.yml)

기존 경쟁사 10곳의 DART 실적 공시와 기사·보도자료 RSS 메타데이터를 수동 수집해 SQLite에 보존합니다. 뉴스는 경쟁사 13곳, 관련 금융그룹, 증권업에 영향을 주는 정책·사업 변화를 5개 주제로 분류합니다. **실제 수집은 수동으로 운영하며, AI 검토 보조도 별도 수동 실행으로만 연결합니다. 정기 실행은 꺼두었습니다.** 경영진 관심사와 등록된 실제 보고 이력은 빈 값입니다.

수집 자료를 **채택·보류·제외**하고 선택한 기간의 채택 자료를 주간 후보 목록으로 모아 복사하거나 CSV로 내보낼 수 있습니다. 제목이 비슷한 자료는 중복 검토 후보로 제안하며 원문을 합치지 않습니다. 선택은 브라우저에 임시 저장되고, **GitHub에 저장** 안내를 따라 별도 수동 워크플로에서 저장소에 보관할 수 있습니다. 후보 선정은 실제 보고 완료가 아닙니다. [사용 방법과 저장 범위](docs/review.md)

DART의 회사명·공시 유형·접수일과 기사·보도자료의 제목·출처·발행일을 바탕으로 AI가 분류·검토 이유·확인할 항목을 제안합니다. 연합인포맥스·뉴스와이어의 출처명 기반 AI 차단을 해제했습니다. 현재는 제목 분석이며 기사 본문 요약이나 실적 수치 분석은 제공하지 않습니다. 앱은 학습·튜닝 작업을 수행하지 않으나 무료 Gemini의 공급자 데이터 이용조건은 별도로 적용됩니다. `GEMINI_API_KEY` 등록과 Free 프로젝트 확인 후 별도 수동 실행이 필요합니다. [설정과 이용 범위](docs/ai.md)

## 수집·저장 범위

- 주제: 실적·자본·주주정책 / 신사업·상품·고객전략 / 제휴·인수·해외사업 / 조직·경영전략 / 정책·인허가·리스크.
- 뉴스 대상 회사: 미래에셋증권, 한국투자증권, NH투자증권, 삼성증권, KB증권, 신한투자증권, 하나증권, 메리츠증권, 토스증권, 카카오페이증권, 다올투자증권, 교보증권, 한화투자증권. 추가 3사의 DART 회사별 출처는 아직 연결하지 않았습니다.
- 관련 금융그룹과 회사명이 없는 업권 기사도 증권·금융 문맥과 사업·정책 변화 조건을 충족하면 포함합니다. 일반 가상자산 시황이나 외부 기업의 모든 뉴스로 확대하지 않습니다.
- DART: 잠정실적, 사업·반기·분기보고서, 감사·연결감사보고서 및 매출액·손익구조 변경 실적 공시만 포함합니다. 실적 발표 예고, 임원·주요주주 지분, 계열사 거래, 배당·자사주·인수 공시 등 다른 유형은 제외합니다. 비상장 경쟁사에도 같은 실적 기준을 적용합니다.
- 기사: 연합인포맥스 증권·IB/기업 RSS. 보도자료: 뉴스와이어 증권 RSS. 화면의 출처명에 기사와 보도자료를 구분합니다.
- 최초 최근 30일, 이후 마지막 성공 범위와 48시간을 겹쳐 조회합니다. DART는 회사별 최대 3페이지, RSS는 출처가 현재 제공하는 최신 항목에 한정됩니다.
- 공개 보존: 회사명·공시명/기사 제목·발행 또는 접수일·원문 링크, 출처와 자체 수집·분류 이력. **본문·RSS 설명문·이미지·첨부·제출인 개인정보는 저장하지 않습니다.** RSS에 시간대가 없으면 시각을 추정하지 않고 날짜만 보존합니다.
- 뉴스 제목의 대상·주제·변화 표현을 설정 파일과 대조해 주분류 1개, AI·디지털자산 등의 보조 태그와 제목 기준 진행 단계를 표시합니다. AI의 중요도 평가·보고 초안이 아니며 회사 경영실적과 상품의 증권발행실적보고서를 구분합니다.
- URL 중복 제거, 변경 버전 보존, 출처별 수집 실패 및 범위 제한 표시를 지원합니다.
- 기존 지분·거래 공시 이력은 SQLite에 보존하되 비활성 처리해 목록·상세 JSON에서 제외합니다. 화면의 건수는 현재 수집 범위 기준입니다.

연결한 RSS가 모든 언론사나 경쟁사 뉴스를 빠짐없이 제공하지는 않습니다. 자료가 없다는 사실을 해당 회사에 변화가 없다는 의미로 해석하지 않습니다. 자세한 조건은 [출처·저장 기준](docs/sources.md)에서 확인합니다.

## GitHub에서 수동 실행

1. **Actions → Manual collection and Pages → Run workflow → main → Run workflow**를 선택합니다.
2. `build`는 오프라인 테스트, 실제 실적 공시목록·뉴스 RSS 수집, 데이터 검증, SQLite·상태·마트 커밋을 수행합니다.
3. `deploy`가 같은 검증 결과를 Pages에 배포합니다. `github-pages`의 주소를 엽니다.
4. 같은 워크플로를 다시 실행해 기존 데이터와 실행 이력이 유지되는지 확인합니다. 변경이 없는 같은 입력은 버전을 추가하지 않습니다. 두 실행 사이 새 공시나 정정이 생기면 건수가 증가할 수 있습니다.

배포 워크플로의 유일한 시작 조건은 `workflow_dispatch`입니다. **Collection checks**는 코드 변경/PR에 오프라인 테스트만 실행합니다. 수집에는 API 키·PAT 등록이 필요 없으며 GitHub 제공 토큰으로 같은 저장소와 Pages에만 기록합니다.

일부 출처 실패는 성공한 자료와 이전 자료를 보존하고 화면에 표시합니다. 전체 수집 실패도 무결성 검증을 통과한 이전 자료와 실패 상태를 보존하며 워크플로는 실패로 표시합니다. 수집 범위가 바뀐 경우에는 기존 자료 중 새 범위에 맞는 항목만 다시 게시하고 실패 사실을 명시합니다. DB/마트 검증 실패 또는 실행 중 main 변경 시에는 강제 덮어쓰기·배포하지 않습니다.

## 개발 검증

운영은 GitHub에서 하며 사용자 PC를 요구하지 않습니다. 개발 환경은 Python 3.12 표준 라이브러리와 JavaScript 구문 검사만 필요합니다.

```sh
python -m unittest discover -s tests -v
python scripts/check_repeatability.py
node --check site/app.js
node --check site/review.js
node --check site/ai.js
node --test tests/test_review.js tests/test_ai.js
python -m weekly_trend collect --root .
python -m weekly_trend verify --root .
```

`collect`/`run`만 실제 출처를 요청합니다. `demo`는 여전히 가상 입력 전용이며 실행 설정을 demo로 바꾼 별도 시험 폴더에서 사용합니다. 운영 config를 복사한 테스트는 시험 폴더만 demo 모드로 바꿉니다.

## 구성

| 경로 | 역할 |
|---|---|
| `config/topics.json` | 5개 주제의 이름과 활성 상태 |
| `config/companies.json` | 뉴스 관찰 회사 13곳과 명칭 |
| `config/classification_rules.json` | 뉴스 주제·변화 키워드, 보조 태그·진행 단계와 업권 범위 |
| `config/sources.json` | 읽어 올 DART 목록·RSS 주소와 공개 저장 범위 |
| `weekly_trend/collectors.py` | 제한된 HTTP/RSS/공개목록 어댑터 |
| `weekly_trend/classification.py` | 설정 규칙을 읽고 제목의 대상·주제·변화를 판단 |
| `weekly_trend/live_storage.py` | 실제 자료 전용 SQLite 테이블과 이력 |
| `weekly_trend/live_pipeline.py` | 수집·상태·마트·무결성 검증 |
| `site/review.js` | 검토 상태·주간 기간·중복 후보·복사/CSV |
| `weekly_trend/reviews.py` | 검토 선택 검증·변경 충돌 방지·저장 |
| `reports/reviews.json` | GitHub에 저장된 검토 선택. 실제 보고 이력과 분리 |
| `data/raw.sqlite3` | 원자료 메타데이터와 실행 이력. 기존 가상 테이블도 보존 |
| `state/`, `site/data/` | 미분석 상태, 출처별 성공/실패, 화면 JSON |
| `reports/history.json` | 빈 실제 보고 이력 |
| `tests/fixtures/` | 오프라인 테스트용 가상 자료 |

저장소와 Pages는 공개입니다. 비밀키·내부자료를 넣지 않습니다. 원문 전체의 자유로운 재배포 권한을 주장하지 않으며, 출처 범위 확대 전 이용조건을 다시 확인합니다.
