# 기사 본문 요약

기사 본문 전체를 바탕으로 **3~6개, 최대 8개의 짧은 개조식 요약**을 표시합니다. 첫 항목은 핵심 사건, 후속 항목은 배경·목적·대상·규모·일정·주요 조건·예외·후속 조치 중 기사에 있는 핵심 내용으로 구성합니다. 명사형 종결을 사용하고 중복을 줄입니다. 진행 단계와 보고 후보 이유는 기사 사실 요약과 별도 AI 검토 의견으로 표시합니다. 기사에 실린 주장과 AI의 검토 의견을 구분하며, 담당자의 채택·보류·제외는 자동으로 바꾸지 않습니다. 일반 수집과 제목 분석은 본문 확보 실패와 무관하게 계속 사용할 수 있습니다.

## 실행

**Daily collection, news AI and Pages**가 매일 한국 시간 오전 8시에 수집 후 요약합니다. 첫 연결 확인은 `main`에서 한 번 수동 실행합니다. 명시적 재시도에는 기존 **Manual AI assistance and Pages**를 사용합니다. 이미 등록한 `GEMINI_API_KEY`를 그대로 사용합니다. 제목 분석에 이어 본문 확보·요약·검증·상태 저장·Pages 배포가 진행됩니다. 새 비밀키나 외부 DB는 필요 없습니다.

- 대상: 현재 수집 목록의 연합인포맥스 기사·뉴스와이어 보도자료. 최초 실행은 최대 5건을 확인합니다.
- DART: 공시 목록과 원문 링크를 수집해 사람이 확인합니다. 공시 서식·회사·날짜·본문 모두 AI로 전송하지 않습니다.
- 네트워크: 자료별 공개 HTML 요청 1회, 최대 2MB·15초. 정상적인 공개 요청만 사용하며 접근 제한·로그인·구독 화면은 우회하지 않습니다.
- AI: 본문용 요청 최대 1회, 기사당 입력 최대 1만 자, 출력 최대 12,288토큰. 제목 분석은 별도 기존 요청이며 캐시가 있으면 추가 호출하지 않습니다.
- 반복: 24시간 안에 동일 입력은 본문 요청과 AI 호출 없이 재사용합니다. 이후 일일 또는 수동 실행 시 본문을 다시 확인하며, 분석 입력이 같으면 AI는 다시 호출하지 않습니다.
- 출처의 본문이 바뀌면 새 요약을 생성합니다. 제목·날짜·출처·근거 버전·프롬프트가 바뀐 예전 결과는 현재 요약으로 표시하지 않습니다.

Actions의 초록색 완료는 검증·상태 저장·배포 성공을 뜻합니다. 실제 요약 성공 여부는 실행 요약의 **본문 요약 완료·확보 실패·분석 실패** 건수와 사이트 자료 상세를 확인합니다. 키 누락이나 사용 한도 초과도 가짜 요약으로 대신하지 않습니다. 기사별 응답을 따로 검사해 정상 요약은 저장하고 오류가 있는 기사만 실패로 표시합니다. 수치·문단·형식 오류는 원응답을 노출하지 않는 개별 상태 코드로 Actions와 화면에 표시합니다.

## 근거와 정확성

기사의 본문 영역을 문단으로 나눠 AI에 전달합니다. 제목과 본문은 지시문으로 실행하지 않고 자료로만 취급합니다. 기사 URL·발행 매체·본문 제목을 확인해 다른 문서의 본문이 잘못 연결되는 경우를 거절합니다.

각 핵심 변화와 주요 사실에는 문단 번호를 연결합니다. AI는 주장별 문단 번호만 선택하며, 짧은 발췌는 프로그램이 해당 원문 문단에서 직접 만듭니다. 모델에 인용문 재현을 맡기지 않습니다. 참조 문단 발췌는 연결된 문단의 미리보기이며 주장을 독립적으로 입증한 별도 자료는 아닙니다. 새 개조식 요약은 항목별 최대 2개 문단을 참조하여 최대 8개 항목의 전체 참조가 16개 이내가 됩니다. 과거 결과 호환을 위한 검증 상한은 항목별 4개·전체 20개입니다. 각 발췌는 8~80자이며, 참조 수에 맞춰 길이를 줄여 기사당 전체 발췌는 최대 200자로 유지합니다. 참조가 많으면 문단 미리보기가 짧아질 수 있습니다. 금액·날짜 등 수치 표현은 연결된 문단의 정확한 숫자·단위·부호와 대조합니다. 없는 값·단위 변경·부분 숫자 일치·음수 부호 누락은 결과 오류로 처리합니다.

이 검사는 출처의 보도 내용이 사실임을 독립적으로 입증하거나 모든 의미 오류를 검출하지는 않습니다. ‘보고 후보 이유’는 별도 AI 검토 의견이며 경영진의 관심사나 확정된 중요도가 아닙니다. 일부 본문만 분석했으면 해당 표시와 본문 확인 시각을 함께 보여줍니다.

## 저장

기사 전문·HTML·이미지·사진 설명·연락처는 저장하지 않습니다. 본문은 요청 처리 중 메모리에만 두고, 요약·최대 200자의 근거 인용·출처 링크·해시·확인 시각·처리 상태만 보존합니다. 이 공개 저장소에서는 저장한 요약과 근거도 공개됩니다. 기존 복사·CSV 내보내기는 원자료 메타데이터 형식을 유지합니다.

앱 자체의 학습·튜닝 작업은 없지만, 무료 Gemini의 입력·출력 데이터 이용조건은 기존과 같이 적용됩니다. 코드에서 분석을 허용하는 것과 출처의 권리 표시·이용허락은 별개입니다. [AI 설정과 이용 범위](ai.md)

| 파일 | 역할 |
|---|---|
| `config/articles.json` | 본문 요약의 실행·분량·캐시 한도 |
| `weekly_trend/article_sources.py` | 공개 본문 요청·기사 식별·문단 추출 |
| `weekly_trend/article_analysis.py` | 근거 검증·AI 호출·캐시·상태 보존 |
| `scripts/analyze_articles.py` | 준비·확인·명시적 수동 실행 |
| `state/article-analysis.json` | 요약 캐시와 실행·확보 상태 |
| `site/data/article-analysis.json` | 현재 목록에 맞춘 공개 요약 상태 |
| `site/article.js` | 화면 데이터 검증과 표시 상태 |

`python scripts/analyze_articles.py --root . --prepare`는 외부 요청 없이 대기 상태를 만듭니다. `--check`는 저장된 자료와 화면 데이터가 일치하는지 확인합니다. `--run`과 일일 실행만 공개 본문 및 AI 요청을 수행합니다. 테스트의 가상 본문·AI 응답은 운영 결과로 저장하지 않습니다.

새 본문 지시문 버전은 `article-bullets-v1`입니다. 숫자 뒤의 문장부호는 수치 표현에 포함하지 않으며, 천 단위 쉼표·소수점·음수 부호·단위는 계속 검사합니다. 한 번의 처리 상한을 넘는 자료는 미분석으로 남아 다음 일일 실행에서 처리합니다.

응답 형식은 전달한 본문의 문단 번호 목록으로 제한합니다. 같은 주장에 중복된 문단 번호는 중복만 제거하며 사실 내용은 바꾸지 않습니다. 없는 문단 번호·빈 근거·주장별 참조 상한 초과는 서로 다른 안전한 오류 코드로 표시합니다. 프롬프트나 출력 형식이 바뀌면 과거 결과는 이력으로 보존하고 새 기준으로 재분석합니다.

## 프롬프트 편집

실제 AI에 전달하는 한국어 프롬프트는 **`config/article_prompt.txt`**입니다. 문체·포함 범위·분량을 이 파일에서 수정할 수 있습니다. 파일 내용은 API의 system_instruction에 그대로 전달하고 입력 지문에도 포함하므로, 프롬프트를 수정하면 이전 요약을 새 기준 결과로 잘못 재사용하지 않습니다.

본문 입력 상한을 수집 상한과 같은 1만 자로 맞췄습니다. 수집·입력 상한 때문에 본문이 잘렸다면 전체 요약으로 표시하지 않고 일부 본문 요약으로 안내합니다. ‘전체 요약’은 본문 전체의 핵심을 빠짐없이 압축하는 뜻이며 기사 전문을 그대로 재현하는 기능이 아닙니다. 현재 기사 6건을 새 형식으로 모두 바꾸려면 최대 5건 처리 상한에 따라 AI 수동 실행이 두 번 필요할 수 있습니다.

자동 실행에서는 같은 입력의 수치·문단·형식 검증 실패를 매일 다시 AI에 보내지 않습니다. 본문은 24시간 뒤 다시 확인할 수 있지만 같은 본문은 실패 상태를 유지합니다. 본문·메타데이터·프롬프트가 바뀌면 새 입력을 처리합니다. 과거 실패에 본문 해시가 없으면 첫 자동 확인에서 해시만 기록하고 AI 재요청은 보류합니다. 명시적으로 재시도하려면 수동 분석을 실행합니다. [일일 처리 상한과 운영](daily.md)
