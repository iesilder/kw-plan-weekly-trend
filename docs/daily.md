# 일일 자동 갱신

`Daily collection, news AI and Pages`가 한국 시간 매일 오전 11시를 기준으로 공개 목록·RSS 수집 → 기사 제목 분류 → 기사 본문 개조식 요약 → 검증·저장 → Pages 배포를 실행합니다. DART는 수집·직접 검토만 하며 AI 입력에 포함하지 않습니다. 채택·보류·제외, 실제 보고 여부와 경영진 관심사는 자동으로 바꾸지 않습니다.

## 처음 한 번

1. 자동 갱신 PR을 `main`에 병합합니다.
2. [Actions → Daily collection, news AI and Pages](https://github.com/iesilder/kw-plan-weekly-trend/actions/workflows/daily.yml) → **Run workflow → main → Run workflow**를 실행합니다. 기존 `GEMINI_API_KEY`를 그대로 사용하므로 새 키 등록은 필요 없습니다.
3. `build`, `deploy`와 실행 요약의 수집·제목 분류·본문 요약 상태를 확인합니다. [사이트](https://iesilder.github.io/kw-plan-weekly-trend/)를 새로고침해 마지막 수집 시각과 요약 건수를 확인합니다.
4. 이후에는 매일 수동 실행할 필요가 없습니다.

스케줄은 `.github/workflows/daily.yml`의 `0 2 * * *` UTC, 즉 같은 날 한국 시간 11:00입니다. GitHub 처리 대기 때문에 정확한 시각에 시작한다고 보장하지 않습니다. 공개 저장소는 60일간 활동이 없으면 예약 실행이 중지될 수 있으며 Actions에서 다시 활성화할 수 있습니다. [GitHub 예약 실행 설명](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)

## 호출·저장 제한

- 하루 저장된 일일 실행 1회: `data/daily-run.json`의 한국 날짜를 확인해 같은 날짜의 일일 재실행은 수집·AI를 생략합니다. 수집 또는 분석 실패가 저장된 날도 자동으로 반복 호출하지 않습니다.
- 제목은 최대 10건·요청 1회, 본문은 최대 5건·요청 1회입니다. 완료된 동일 입력은 캐시를 재사용하며 상한을 넘는 자료는 다음 날로 넘깁니다. 본문 확인은 캐시 24시간 뒤 다시 할 수 있지만 동일 본문을 다시 AI에 보내지 않습니다.
- 같은 본문·메타데이터·프롬프트에서 검증 실패한 결과는 자동 재요청을 보류합니다. 변경된 입력은 새로 처리합니다. 과거 실패에 본문 지문이 없으면 첫 자동 본문 확인에서 지문만 저장합니다. 명시적 재시도는 수동 분석 워크플로로 가능합니다.
- 네트워크·공급자 한도 등 일시 오류는 다음 날 다시 시도할 수 있습니다. 한 실행 안에서 즉시 재시도하거나 유료 모델로 대체하지 않습니다.
- 일일 날짜 제한은 **저장 완료된 실행** 기준입니다. API 호출 뒤 저장·푸시 전에 실행이 중단되거나 충돌하면 재실행에서 중복 호출할 가능성이 있습니다. 기존 수동 워크플로는 이 일일 제한과 별도로 명시적 재시도를 허용합니다.
- 기존에 확인한 **Free·Cloud Billing 미연결 프로젝트**의 Secret을 사용한다는 전제로 자동 실행합니다. 코드가 API 키로 프로젝트 결제 상태를 조회하지는 않습니다. 키 교체 시에도 같은 조건을 유지합니다.

## 오류와 게시

수집·제목 분류·본문 요약 상태는 각각 기록합니다. 기사별 오류는 정상 요약과 원자료를 보존하고 사이트 갱신을 계속합니다. 초록색 워크플로 완료가 모든 기사 분석 성공을 의미하지는 않습니다. 실행 요약과 사이트의 실패·대기 건수를 함께 확인합니다.

전체 출처 수집 실패 시 검증된 이전 자료와 실패 상태를 게시하고 워크플로를 실패로 표시합니다. 수집 단계 자체의 예외는 기존 자료를 검증하고 그 실행의 AI를 생략합니다. DB·화면 데이터 무결성 오류는 게시하지 않습니다. 실행 중 `main`이 바뀌면 강제로 덮어쓰거나 오래된 산출물을 배포하지 않습니다.

수집·분석·검토 저장 워크플로는 같은 실행 잠금을 사용합니다. 수동 작업과 예약 작업이 동시에 데이터를 쓰지 않도록 하며, 수집 후에도 사람의 검토 선택과 기존 요약 캐시를 보존합니다. 여러 작업을 연달아 요청하면 GitHub가 대기 중인 실행을 새 실행으로 대체할 수 있습니다.

## 멈추거나 별도로 실행할 때

예약 실행을 중지하려면 Actions에서 이 일일 워크플로의 **Disable workflow**를 선택합니다. 코드로 끄려면 cron을 제거하고 `config/pipeline.json`의 `schedule_enabled`를 false로 바꿉니다. 수집만 필요하면 `Manual collection and Pages`, 실패 자료의 명시적 분석 재시도는 `Manual AI assistance and Pages`를 사용합니다. 사용자 PC나 외부 DB는 필요 없습니다.
