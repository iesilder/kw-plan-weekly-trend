# 경영진 관심사 등록과 별도 수집

관심사를 등록·수정한 뒤 사이트로 돌아오면 등록 목록을 바로 읽어 표시합니다. 새 관심사는 **등록됨 · 수집 대기**, 수정한 관심사는 **변경됨 · 수집 대기**로 표시합니다. 다음 한국 시간 오전 11시 배치가 실제 수집에 적용할 등록부를 읽어 기존 5대 주제와 함께 수집합니다. 사이트의 **관심사 지금 수집**으로 수집 요청을 제출하면 정기 배치를 기다리지 않고 별도 작업을 실행합니다. 기존 SQLite·GitHub Actions·Pages를 사용하며 새 서버·DB·개인 토큰은 필요 없습니다.

## 관심사 등록

1. 사이트의 **관심사 등록**을 누릅니다. GitHub에 로그인된 계정으로 등록 양식이 열립니다.
2. 관심 주제, 보고 질문, 검색어, 분류를 입력합니다. 검색어는 쉼표나 줄바꿈으로 구분하며 하나 이상 일치하면 해당 관심사에 연결합니다. 제외 검색어가 일치하면 그 관심사 연결에서 제외합니다.
3. 시작일·종료일을 지정할 수 있습니다. 시작일을 비우면 처음 등록한 한국 날짜, 종료일을 비우면 중지할 때까지 적용합니다. 날짜를 비운 채 수정해도 최초 시작일을 매일 다시 바꾸지 않습니다.
4. 공개 저장 안내를 확인하고 GitHub의 **Submit new issue**를 누릅니다. 실제 저장이 끝난 시점에 등록됩니다.

관심 주제와 보고 질문 등 입력 내용은 공개됩니다. 공개 가능한 업무 기준만 적습니다. 현재 운영 계정 `iesilder`가 등록한 양식만 처리하며, 일반 방문자의 글과 PR은 관심사에 반영하지 않습니다. 활성 기간이 겹치는 관심사는 최대 20개, 관심사당 검색어와 제외 검색어는 각각 최대 10개입니다.

관심사 목록은 공개 GitHub 등록 글을 직접 읽어 표시합니다. 등록·관리 화면에서 저장하고 사이트로 돌아오면 새 목록을 확인하며, **등록 목록 새로고침**으로 직접 다시 확인할 수 있습니다. 등록 확인 시각과 실제 기사 수집 시각은 별도로 표시합니다. 등록 내용을 확인하는 작업은 기사 수집이나 AI 요청을 실행하지 않습니다.

기사 연결·요약과 최근 수집 결과는 마지막 실제 수집 자료를 사용합니다. 새 관심사와 검색 조건을 바꾼 관심사는 새 수집 전까지 대기로 표시하며, 이전 조건의 결과를 새 조건의 수집 완료로 표시하지 않습니다. 등록 글을 닫거나 기간이 끝나면 목록에 즉시 중지·기간 종료 상태를 표시하고, 실제 수집 설정과 자료 공개 범위는 다음 배치 또는 별도 수집에서 반영합니다.

브라우저는 토큰 없이 공개 등록 글만 조회합니다. 일반적인 화면 복귀는 최근 조회를 재사용하고, 등록·수정 직후 복귀와 직접 새로고침은 새 내용을 확인합니다. GitHub 조회 실패·요청 한도 초과 시 마지막 정상 목록 또는 게시된 목록을 보존하며 확인 실패를 표시합니다. 실패를 미등록·기사 0건으로 표시하지 않습니다. **관심사 지금 수집**은 등록 수와 관계없이 사용할 수 있습니다.

## 정기 배치와 지금 수집

매일 오전 11시 배치는 시작 시점에 등록부를 읽습니다. 그 이후에 추가·수정한 내용은 다음 배치 또는 별도 수집에 반영합니다. 같은 한국 날짜에 완료한 정기 실행을 다시 실행하면 생략하는 기존 제한은 유지합니다.

**관심사 지금 수집**을 누르면 GitHub의 수집 요청 양식이 열립니다. 요청 확인에 체크하고 **Submit new issue**를 눌러야 실제 실행됩니다. 요청은 **Collect executive interests and Pages**에서 처리합니다. 실행·배포가 끝나면 사이트의 **자료 다시 불러오기**로 새 결과를 확인합니다. GitHub Actions의 같은 워크플로에서 **Run workflow**로 직접 실행할 수도 있습니다.

별도 수집은 현재 등록된 관심사를 먼저 새로 확인합니다. 승인된 뉴스 RSS에서 관심사에 맞는 자료를 확인하며 기존 일반 수집의 기준 시각과 조건부 요청 정보를 앞당기지 않습니다. 같은 요청의 저장 완료 이력을 재실행하면 수집·API 호출을 반복하지 않습니다. 새로운 수집 요청은 같은 날에도 실행할 수 있습니다. 게시까지 완료한 요청 글은 자동으로 닫아 처리 완료로 표시하며, 관심사 등록 글은 계속 열어둡니다. 요청 글을 닫는 단계가 실패해도 이미 완료한 게시를 취소하지 않습니다.

사이트 코드 변경을 main에 병합하면 이 워크플로가 저장된 자료를 준비·검증해 화면을 게시합니다. 이 게시 전용 실행은 외부 기사 수집이나 AI 호출을 하지 않습니다.

## 수집 범위와 중복 처리

- 기존 5대 주제와 관심사 조건 중 하나를 충족하는 자료를 보존합니다. 관심사 전용 자료도 지정한 5대 분류 중 하나에 연결합니다.
- 최초 또는 검색 조건 변경 시 해당 관심사에 한해 최근 30일 범위에서 확보 가능한 자료를 확인합니다. 이후에는 관심사·출처별 마지막 성공 시점과 48시간을 겹쳐 조회합니다. 기존 일반 수집의 기준 시점과 따로 관리합니다.
- 기사 한 건이 여러 관심사에 해당해도 원자료와 요약은 공유합니다. 관심사 수정 자체를 기사 원문의 수정으로 기록하지 않습니다.
- 조회는 연결된 연합인포맥스·뉴스와이어 RSS 제공 범위에 한정합니다. 임의의 언론사·전체 웹 검색이나 과거 30일 기사 전체 복원을 보장하지 않습니다.
- 기존 경쟁사·증권업 관련 범위와 명백한 시세·홍보 제외 기준을 유지합니다. 관심사 검색어가 있다는 이유만으로 모든 기사를 수집하지 않습니다.
- DART는 기존 실적 공시 범위를 유지하며 AI에 전송하지 않습니다. 별도 관심사 수집은 뉴스 RSS를 확인합니다.

관심사별 화면 결과는 최근 30일 자료의 **제목 검색어 일치** 기준입니다. 제공된 원문 수정 시각이 최근이면 오래된 발행 자료도 포함할 수 있습니다. 발행·수정 시각이 모두 없을 때는 최초 확인 시각을 사용합니다. 본문에만 검색어가 있는 기사는 연결하지 못할 수 있습니다. 보고 질문은 담당자의 검토 기준으로 표시하며, 경영진의 의도나 중요도를 자동으로 확정하지 않습니다.

## 기사 분석과 상태 확인

정기 실행은 새 관심사 연결 자료를 우선 처리합니다. 별도 수집의 AI 요청은 활성 관심사에 연결된 기사로 한정합니다. 기존 사실 요약과 정상 캐시를 재사용하며 제목 최대 10건·요청 1회, 본문 최대 5건·요청 1회의 상한을 유지합니다. 처리 한도 초과 자료는 대기로 남습니다. 같은 입력의 검증 실패는 기존 자동 재요청 보류 규칙을 적용합니다.

관심사 카드에서 마지막 확인 시각, 처리 상태, 현재 연결 기사 수와 제목의 일치 검색어를 확인할 수 있습니다. 0건은 연결된 출처·확보 범위에서 현재 일치한 자료가 없다는 뜻입니다. 등록부 조회 실패·수집 실패·미확인은 0건과 구분합니다. 등록부 조회 실패 시 이전 정상 설정을 보존하며 정기 일반 수집은 계속합니다. 별도 요청은 새 등록 내용을 확인하지 못한 경우 수집을 중단하고 실패 상태를 표시합니다.

## 수정·중지

관심사 카드의 GitHub 링크에서 등록 글을 수정하고 사이트로 돌아오면 변경 내용을 즉시 표시합니다. 실제 수집 조건은 다음 배치 또는 별도 수집에 반영합니다. 종료일이 지나거나 글을 **Close issue** 하면 활성 적용을 중지합니다. 과거 등록 이력과 원자료·요약·담당자의 검토 선택은 삭제하지 않습니다. 별도 관심사에만 해당하던 자료는 활성 관심사와 기본 수집 기준에 따라 공개 목록에서 제외될 수 있으며 SQLite 이력은 보존합니다.

## 운영 기록

| 경로 | 용도 |
|---|---|
| GitHub 관심사 등록 글 | 등록·수정·종료의 기준 |
| `config/interests.json` | 배치가 검증해 저장한 정규화된 등록부 |
| `data/interests-registry.json` | 등록부 확인 성공·실패 시각 |
| `data/interests-collection.json` | 관심사·출처별 조회 기준 시점과 결과 |
| `data/interests-requests.json` | 저장된 별도 요청 처리 이력 |
| `site/data/interests.json` | 현재 자료 버전에 맞춘 화면 상태와 연결 기사 |

API 호출 뒤 커밋 전에 작업이 중단되거나 main이 변경되면 저장 전 호출을 다시 수행할 수 있습니다. 저장된 요청에 대한 중복 방지는 엄격한 공급자 단위 일일 과금 한도나 장애 구간의 완전한 1회 실행 보장을 뜻하지 않습니다. 기존 Free·결제 미연결 프로젝트와 호출 상한을 유지합니다.
