# 실제 보고 이력과 중복 확인

`history.html`에서 실제 전달한 **보고 제목 + 핵심 문구 + 보고일**과 근거 기사(최대 20개)를 기록합니다. 한 보고 항목에 여러 기사를 연결할 수 있고, 같은 날짜로 여러 항목을 기록할 수 있습니다. 후보 채택·복사·CSV 내보내기는 실제 보고 완료가 아닙니다. 실제 전달 여부와 공개 저장 여부를 각각 확인해야 저장 요청을 만들 수 있습니다.

## 저장

- 브라우저 초안은 선택적으로 로컬에만 보관되며 공식 보고 이력이나 중복 비교 기준이 아닙니다.
- 화면에서 JSON을 만들고 `Save delivered reports and Pages`의 `report_patch` 입력에 붙여 넣습니다. 이 동작은 인증된 저장소 쓰기 권한을 가진 사람이 GitHub에서 실행합니다. 브라우저에 PAT/API 키를 넣지 않습니다.
- 워크플로는 수집·AI 호출 없이 입력 검증 → 버전 충돌 확인 → 기록 저장 → 배포를 수행합니다. 저장 요청 JSON 생성·복사 자체는 저장 성공이 아닙니다. 배포 뒤 ‘저장 결과 다시 확인’으로 반영 여부를 확인합니다.
- 같은 요청 ID의 동일 JSON은 중복 등록하지 않습니다. 저장된 버전이 달라졌다면 덮어쓰지 않고 거절합니다. 새로 불러온 뒤 내용을 확인하고 다시 생성합니다.
- 정정·완료 취소는 이전 내용을 지우지 않고 버전을 추가합니다. 취소한 항목은 비교에서 제외하지만 이력 검색에서 다시 볼 수 있습니다. 과거 근거의 제목·출처·날짜·URL은 기사 갱신이나 삭제와 무관하게 유지합니다.
- 현재 모든 내용은 **공개 저장소·사이트·워크플로 입력에 공개**됩니다. 비밀·내부 전용 문구를 넣지 마세요. 로그인 UI만으로 정적 데이터 주소를 보호할 수 없습니다. 실제 접근 통제는 별도 기능입니다.

## 중복 비교

기사 상세에서 관련 보고 최대 3개, 이력 화면에서 최대 10개를 표시합니다. 동일 기사 ID/정규화 URL은 ‘이미 보고에 사용한 자료’, 제목과 과거 보고 제목·핵심 문구·근거 제목에 겹치는 표현이 일정 기준 이상이면 ‘중복 가능성’으로 표시합니다. 같은 기업이라는 이유만으로 중복 처리하지 않습니다. 자동 삭제·제외·보고 확정은 하지 않습니다.

이 비교는 제목·메타데이터 기반 규칙이며 의미 기반 사건 판정·AI 비교·후속 변화 자동 확정이 아닙니다. 동일 기사도 정정됐을 수 있고, 관련 후보가 없다고 신규 이슈가 증명되는 것은 아닙니다. 최종 판단은 담당자가 합니다. 실제 보고 문구를 외부 AI에 보내지 않습니다.

## 데이터 구조

- 공식 원장: `reports/delivered.json`
- 공개 독립 사본: `site/data/delivered-reports.json`
- 수집 파이프라인은 공식 원장을 검증하고 사본을 보존합니다. 수집 결과의 세대 ID와 별개인 `revision`으로 버전을 관리합니다.
- 기존 `reports/history.json` 및 `site/data/report-history.json`은 초기 데모/수집 무결성용 빈 호환 필드입니다. 실제 보고 수·기록의 권위 있는 자료가 아닙니다. 실제 보고는 이력 페이지의 공식 원장을 기준으로 표시합니다.
- 운영 원장에는 가상 보고나 과거 보고를 자동 생성하지 않습니다. 시험 데이터는 테스트 임시 폴더에서만 사용합니다.

## 현 단계 한계

직접 저장 API가 없는 GitHub Pages이므로 공식 저장에는 GitHub 워크플로 수동 실행이 필요합니다. 회차별 일괄 확정·의미 기반 이슈 묶기·후속 변화 분석·과거 문서 자동 가져오기는 포함하지 않습니다.
