# 3단계 · 보고 후보 검토

공개 자료에서 보고 후보를 직접 고릅니다. 채택·보류·제외는 검토 상태이며, 실제 보고 완료 이력이나 AI의 중요도 평가가 아닙니다. 경영진 관심사와 실제 보고 이력은 계속 빈 값입니다.

## 사용 순서

1. 자료의 원문을 확인하고 상세 화면에서 **채택 / 보류 / 제외 / 미검토**를 선택합니다. 목록의 검토 상태 필터로 다시 찾을 수 있습니다.
2. **주간 보고 후보**에서 발행·접수일 기준 기간을 선택합니다. 기본은 한국 시간 월요일~일요일입니다. 선택한 기간의 채택 자료만 회사·주제별로 표시합니다.
3. 후보 목록을 복사하거나 CSV로 내려받습니다. 제목·회사·주제·출처·발행일·원문 링크만 포함하며, 기사 본문·요약·추정 실적·시사점을 생성하지 않습니다.
4. 선택을 GitHub에 보관하려면 **GitHub에 저장**을 열고 준비된 JSON을 복사합니다. 안내된 **Save review choices and Pages** 워크플로에서 **Run workflow → review_patch에 붙여넣기 → Run workflow**를 실행합니다. 완료 후 사이트에서 자료를 다시 불러옵니다.

## 임시 저장과 GitHub 저장

선택 즉시 같은 브라우저의 저장 공간에 임시 저장합니다. 별도 프로그램이나 사용자 PC에서 실행할 서버는 필요하지 않습니다. 다른 기기와 자동으로 공유되지는 않으며, 브라우저 데이터를 지우면 임시 선택은 사라집니다. 임시 선택의 JSON 백업·불러오기도 제공합니다.

GitHub 저장은 로그인된 저장소 운영자가 수동 Actions로 실행합니다. 브라우저에 GitHub 토큰을 입력하거나 저장하지 않습니다. GitHub Pages 자체에는 인증된 쓰기 서버가 없기 때문에 선택 버튼을 누르는 것만으로 저장소가 갱신되지는 않습니다.

저장되는 값은 자료 ID, 검토 상태, 저장 시각 및 변경 번호입니다. **현재 저장소와 Pages는 공개이므로 GitHub에 저장한 검토 상태도 공개됩니다.** 내부 보고 문구·메모·경영진 관심사 입력란은 제공하지 않습니다.

다른 사람이 먼저 저장해 변경 번호가 바뀌면 덮어쓰지 않고 충돌을 표시합니다. 최신 GitHub 상태를 확인한 후 선택을 다시 정리합니다. 이미 같은 선택이 저장되었다면 브라우저의 해당 임시 변경은 정리합니다.

## 중복 후보의 의미

같은 회사·대상과 주제, 가까운 발행일, 유사한 제목을 근거로 중복 가능성을 표시합니다. AI 분석이나 동일 사건 확정 결과가 아닙니다. 각 자료와 원문 링크는 그대로 유지하며, 채택·보류·제외도 각각 결정합니다. 날짜를 확인할 수 없거나 진행 단계가 다른 자료는 무리하게 묶지 않습니다.

발행일이 확인되지 않은 자료를 수집일로 대체해 주간 목록에 넣지 않습니다. 현재 수집 범위 밖으로 빠진 자료의 기존 선택은 보존하되 현재 후보 목록에는 표시하지 않습니다. 원문 링크를 확인하지 못하면 내보내기를 완료한 것처럼 표시하지 않습니다.

## 저장 및 처리 위치

| 경로 | 역할 |
|---|---|
| `site/review.js` | 검토 상태, 날짜 범위, 중복 후보, 복사·CSV 데이터 처리 |
| `site/app.js` | 검토 버튼과 주간 목록, 임시 저장, GitHub 저장 안내 |
| `reports/reviews.json` | GitHub에 저장된 검토 결과의 기준 파일 |
| `site/data/reviews.json` | Pages가 읽는 검토 결과 복사본 |
| `weekly_trend/reviews.py` | 입력 검증, 변경 번호 검사, 검토 결과 보존 |
| `scripts/apply_reviews.py` | 수동 워크플로에서 검토 선택 적용 |
| `.github/workflows/reviews.yml` | 기사 수집 없이 검토 결과만 저장·배포 |

기존 수동 수집도 저장된 검토 결과를 유지합니다. AI 호출·정기 실행은 계속 꺼져 있으며, 검토 상태 저장 워크플로도 수동으로만 실행됩니다.
