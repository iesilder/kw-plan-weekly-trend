# 1단계 개발 범위

## 확정 조건

- 주제는 실적·자본·주주정책, 디지털·AI·신사업, 제휴·인수·해외사업, 조직·경영전략, 규제·위험·운영의 다섯 가지입니다.
- 실제 수집을 연결하는 후속 단계에서는 하루 한 번 배치를 전제로 합니다. 이번 단계에서는 수동 가상 데이터 처리만 제공합니다.
- 출처 수를 과도하게 늘리지 않고 신뢰할 수 있는 기존 후보를 유지합니다. `config/sources.json`은 비활성 설정이며 실제 수집 가능성이나 재배포 권한을 보증하는 목록이 아닙니다.
- 경영진 관심사를 추정하지 않습니다. `config/interests.json`의 관심사는 빈 배열입니다.
- 실제 보고 이력을 추정하지 않습니다. `reports/history.json`은 빈 배열이며, 보고 여부를 단정하지 않습니다.

## 데모 데이터 원칙

가상의 A~E 증권과 `demo://fixture/` 식별자를 사용합니다. 실존 경쟁사에 허구의 실적·사고·정책을 귀속시키지 않습니다. 외부 기사로 오인할 수 있는 원문 링크를 만들지 않으며, 모든 근거의 `source_url`은 null입니다. 화면의 요약·우선순위·변경 내용은 고정된 가상 규칙으로 생성하며 AI 분석으로 표시하지 않습니다.

경쟁사 설정은 별도의 초안입니다. 실제 입력에 적용하는 수집 대상 확정은 후속 단계의 작업입니다.

## 처리 흐름

수동 워크플로는 가상 입력과 현재 SQLite를 읽고, 임시 작업 영역에서 기사 식별·변경 버전 저장·이슈 묶음·정적 JSON을 생성합니다. 검증을 통과한 결과만 저장소에 반영하고 `site/`를 배포합니다. 같은 기사의 이전 버전과 기존 실행 이력을 보존합니다.

실제 실행 로그는 허구로 만들지 않습니다. 로컬 테스트 결과와 GitHub Actions 실행·Pages 배포 결과는 구분하여 기록합니다.

## 후속 단계에서 결정할 항목

1. 실제 출처별 이용 조건과 공개 저장 필드, 최초 운영 대상 회사
2. 수집 API/RSS 연결 및 인증정보를 비공개로 보관할 위치
3. 하루 한 번 실행 시각, 실패 알림과 재처리 방식
4. AI 모델·비용 한도·출력 검증 기준
5. 실제 경영진 관심사와 보고 이력을 공개 사이트와 분리할 방식

위 항목은 이번 데모에 연결하지 않습니다.
