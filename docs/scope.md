# 실제 수집 및 보고 후보 검토 범위

- 기존 경쟁사 10곳을 유지하고 뉴스 관찰 대상에 다올투자증권·교보증권·한화투자증권을 추가합니다. DART 출처는 기존 검증된 10곳입니다. 5개 주제는 실적·자본·주주정책 / 신사업·상품·고객전략 / 제휴·인수·해외사업 / 조직·경영전략 / 정책·인허가·리스크로 조정합니다.
- GitHub Actions에서 수동 수집하고 SQLite·상태·마트를 저장소에 기록한 뒤 Pages에 배포합니다.
- AI 호출, 정기 실행, 외부 DB, 사용자 PC에서의 운영은 연결하지 않습니다.
- 경영진 관심사와 실제 보고 이력은 빈 값으로 유지합니다.

## 실제로 보존하는 내용

DART 공개 회사별 공시목록에서 잠정실적 및 실제 실적을 담는 정기·감사보고서만 포함합니다. 실적 예고, 임원지분, 대량보유, 계열거래 등 다른 공시는 제외합니다. 회사명, 법정 공시서식명, 접수번호를 포함한 원문 링크, 접수일만 수집합니다. 비상장 회사에도 같은 실적 기준을 적용합니다. 수집 시각·출처·저장 근거·제목 분류 결과는 자체 처리 이력으로 추가합니다. 접수 시각은 목록에 없으므로 만들어 넣지 않고 날짜만 기록합니다. 공시 본문, 재무 수치, 첨부, 이미지, 제출인 개인정보는 요청하거나 저장하지 않습니다.

연합인포맥스 증권·IB/기업 기사와 뉴스와이어 증권 보도자료 RSS를 연결합니다. 제목·발행일·원문 링크·출처만 보존하고 RSS 설명문·기사 본문·사진은 버립니다. 시간대 없는 발행값은 날짜만 기록합니다. 뉴스는 경쟁사·관련 금융그룹·증권업권의 변화 중 5개 주제에 해당하는 제목을 포함하며, 기업 보도자료를 독립 취재 기사와 구분합니다.

DART 전체 콘텐츠에 대한 포괄 재배포 허락을 의미하지 않습니다. OpenDART API의 이용허락을 이 수집 경로에 적용하지 않습니다. 자세한 확인 결과는 [출처·저장 기준](sources.md)에 있습니다.

## 분류와 화면

회사별 검증된 고유번호와 실적 공시서식 허용 목록으로 DART 자료를 선별합니다. 뉴스는 `config/classification_rules.json`의 대상·주제·변화 규칙을 함께 적용합니다. AI·디지털자산 등은 보조 태그로 주제에 걸쳐 표시하며 진행 단계는 제목에서 확인되는 표현만 사용합니다. 원문을 읽은 의미 분석이 아니므로 본문에만 나타나는 주제는 누락될 수 있습니다. 상품 판매 관련 투자설명서·일괄신고추가서류·증권발행실적보고서를 회사 경영실적으로 분류하지 않습니다. 고객이 받은 배당을 증권사 자체 주주환원으로 분류하지 않으며 증권 인수업을 기업 인수로 혼동하지 않도록 제목 규칙을 구분합니다. 세부 규칙과 수정 위치는 [분류 기준](classification.md)에 정리합니다.

현재는 URL별 자료를 독립 항목으로 표시합니다. 같은 사건인지 불명확한 공시를 임의로 병합하지 않습니다. AI 분석 완료, 중요도 평가, 보고 초안, 기보고 여부를 만들어 표시하지 않습니다. 실제 데이터와 가상 데이터는 DB와 화면에서 구분합니다.

## 실패와 재실행

- 최초 최근 30일의 목록, 이후 성공 지점부터 48시간을 겹쳐 수집합니다.
- 수집 정책이 변경된 출처는 최근 30일을 재확인합니다. 기존 자료도 새 규칙으로 다시 분류하며, 새 범위를 벗어난 항목은 이력을 보존하되 현재 목록·상세에서 제외합니다. RSS에서 이미 사라진 과거 기사를 복원하는 기능은 아닙니다.
- 회사별 최대 3페이지·300건으로 요청량을 제한합니다. 페이지가 잘렸거나 실패하면 성공 범위를 전진시키지 않습니다.
- 같은 URL·같은 메타데이터는 버전을 추가하지 않습니다. 제목 또는 날짜 변경은 새 버전으로 보존합니다.
- 일부 출처 실패 시 이전 자료와 성공한 출처의 결과를 보존하고 출처별 실패를 표시합니다.
- 전체 실패 시 이전 정상 목록을 유지하고 실패 상태를 표시합니다. 첫 실행 실패는 정상적인 자료 0건으로 표시하지 않습니다.
- 정책이 변경된 상태에서 전체 실패하면 기존 정상 자료 중 새 범위에 맞는 자료만 게시하고, 수집 실패와 범위 변경 적용을 함께 표시합니다.
- 검증에 실패한 DB·마트는 배포하지 않습니다. main이 실행 도중 바뀌면 강제 덮어쓰기를 하지 않습니다.

## 다음 단계

3단계에서 채택·보류·제외 검토 상태, 제목 유사도 기반 중복 후보, 기간별 채택 목록과 복사·CSV 내보내기를 추가합니다. 선택은 브라우저에 임시 저장하고 별도 수동 워크플로로 GitHub에 보관합니다. 수집·재배포 때도 검토 상태를 유지하며, 실제 보고 완료 이력은 생성하지 않습니다. 자세한 사용법은 [보고 후보 검토](review.md)를 확인합니다.

AI 사실 분석·중요도 평가·초안 생성, 실제 보고 이력 비교, 정기 실행은 후속 단계입니다. 이번 단계에서는 활성화하지 않습니다.
